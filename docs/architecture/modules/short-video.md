# Короткие видео (этап 22)

`posts.kind=short_video` отделяет вертикальный ролик от обычного поста с видео. В редакторе выбирается один исходный файл для всех каналов; `PostOptions.shortVideo` хранит заголовок, приватность, детскую аудиторию, параметры взаимодействий, рекламу, теги, обложку и выбор ленты Reels. Доступные поля задают `Capabilities::shortVideoFields`. VK Клипы остаются выключенными до официального контракта API ([ADR 0027](../../adr/0027-short-video.md)).

## Загрузка и медиа

`ChunkedVideoUploads` принимает упорядоченные части до 8 МиБ в приватный временный каталог. Сессия привязана к пространству и загрузившему человеку, сервер проверяет смещение и после сборки сравнивает SHA-256. Незавершённые сессии удаляются через 24 часа. `MediaService` повторно проверяет тип файла, длительность, размер и квоту. Начальный максимум 1024 МиБ / 180 секунд задаётся в `/admin/settings`; тариф и правила платформы могут быть строже. `VideoCovers` создаёт JPEG из выбранного кадра; можно также выбрать изображение из медиатеки. `VideoVariantService` создаёт кэшированный MP4 H.264/AAC без исходных метаданных с `+faststart`. Вычислительная работа идёт в отдельной очереди `video` с одним worker. Для TikTok и Instagram ссылка на вариант подписывается через `MediaUrls::signed`; TikTok PULL_FROM_URL требует S3 и подтверждённый HTTPS префикс.

## Публикация и восстановление

`PublishJob` для короткого видео попадает в `video`. После принятия файла TikTok или YouTube `Publisher` сохраняет `PublicationStatus::Processing`; `VideoProcessingJob` опрашивает сеть с увеличивающейся паузой, а планировщик восстанавливает потерянные проверки. Instagram Reels ждёт готовности контейнера ограниченное время в том же `video-worker` перед вызовом `media_publish`. Запись `video_provider_sessions` хранит зашифрованный resumable URL, подтверждённое смещение, внешний ID и срок ожидания. После завершения статус становится `sent`; отказ сети — `failed`; истечение срока или неясный результат — `unknown`, без автоматической повторной загрузки. YouTube сверяет последние загрузки канала по уникальной метке в тегах перед признанием неопределённого результата отправленным. Подробности общих переходов — [publishing](publishing.md).

`video_upload_quota_days` и `video_upload_quota_reservations` считают вызовы YouTube `videos.insert` во всём проекте. Резервирование перед вызовом атомарно и не отменяется при сетевой ошибке, поскольку Google может списать квоту. Планирование учитывает уже зарезервированные и будущие вызовы; сутки начинаются в полночь America/Los_Angeles. Лимит `YOUTUBE_DAILY_UPLOAD_LIMIT` должен совпадать с квотой проекта. Остаток и очередь доступны в `/admin/stats`; там же — количество видео по сетям и длительность обработки p50/p95.

## Данные и доступ

Миграции 51–54 добавляют тарифные лимиты, три таблицы для видео и сведения о кодеке звука и частоте кадров. Все пользовательские операции проходят через контекст пространства; URL загрузочной сессии доступен только worker и шифруется `Crypto`. Токены платформ лежат только в `CredentialVault`. Состояния `processing` учитываются в статусе поста, календаре и ограничениях на редактирование. Адаптеры никогда не вызывают реальные сети в тестах: HTTP подменён `MockHttpClient`.
