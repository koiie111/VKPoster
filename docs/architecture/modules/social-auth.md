# Вход через соцсети (этап 03)

Код: `src/Integrations/OAuth` (провайдеры), `src/Domain/Auth/Social` (правила и хранилище), `src/Http/Auth/SocialFlow.php` (состояние в сессии), контроллеры `Auth/SocialController`, `Account/LoginMethodsController`.

## Провайдеры
| id | Как работает | Почта считается подтверждённой |
|---|---|---|
| `vkid` | id.vk.com, код + PKCE S256, `device_id` | нет |
| `yandex` | oauth.yandex.ru, код + PKCE, `login:email login:info` | да (`default_email`) |
| `google` | OIDC, `id_token` проверяется по JWKS | да, если `email_verified=true` |
| `telegram` | Login Widget, подпись HMAC-SHA256, `auth_date` ≤ 24 ч | почты нет |
| `fake` | только `APP_ENV=local|testing` и `DEV_OAUTH_FAKE=1` | задаётся на форме `/dev/oauth/fake` |

Провайдер без ключей в `.env` скрыт: `/auth/{id}/...` отвечает 404, кнопки нет (`ProviderRegistry` — белый список).

## Маршруты
- `GET /auth/{provider}/redirect[?next=/path]` (гости): `state`, PKCE и `nonce` кладутся в сессию (`oauth.flow.<provider>`, 10 минут), редирект на хост провайдера (`Response::redirectToTrusted`). `next` принимается только как относительный путь.
- `GET /auth/{provider}/callback`: `state` достаётся из сессии один раз и сравнивается `hash_equals`; затем обмен кода, профиль, решение. Для Telegram `state` передаётся в `data-auth-url` виджета, а подпись каждого ответа принимается один раз (Redis, 24 ч).
- `GET|POST /auth/social/consent`: шаг согласия на обработку ПДн для нового аккаунта.
- `GET /account/login-methods`, `POST .../{provider}/link`, `POST .../{provider}/unlink`, `POST .../password`.

## Правила сопоставления (`SocialAuthService::resolve`)
1. Известный аккаунт провайдера: вход (заблокированный пользователь получает отказ).
2. Пользователь уже вошёл: аккаунт привязывается, если он ничей и у пользователя нет другого аккаунта этого провайдера.
3. Подтверждённая почта провайдера совпала с существующим аккаунтом: автоматического входа и слияния нет. Профиль откладывается в сессию на 10 минут и привязывается после входа по почте и паролю этого аккаунта (если его почта та же).
4. Иначе: новый аккаунт после согласия. Почта сохраняется, только если её подтвердил провайдер; иначе `users.email = NULL` (нечего подтверждать, почту можно добавить позже).

Если включена 2FA, после соц.входа запрашивается код (`/login/2fa`). Последний способ входа отвязать нельзя; пароль считается способом, только если у аккаунта есть и почта, и пароль.

## Безопасность
- Состояние входа живёт в серверной сессии и привязано к браузеру; `state` одноразовый.
- `id_token` Google: только RS256, подпись по JWKS, `iss`, `aud`, `exp`, `nonce`.
- Привязка возможна только из вошедшей сессии (`POST` + CSRF), а `intent=link` проверяется ещё раз при возврате.
- CSP для виджета Telegram (`script-src https://telegram.org`, `frame-src https://oauth.telegram.org`) добавляется только на страницах с виджетом: `/login` и `/account/login-methods`.
- Токены провайдеров после чтения профиля не сохраняются.

Подробнее о выборе без библиотек: ADR 0004. Как добавить провайдера: `howto-oauth-provider.md`.
