# Метрики бизнес-дашборда

Считает `Analytics\MetricsAggregator` в таблицу `metrics_daily` (день UTC, метрика, разрез `dim`, значение), читает `MetricsReader`. Деньги в копейках, у каждой суммы своя валюта: разные валюты никогда не складываются, на дашборде выбирается одна.

## Откуда берутся числа
| Что | Источник |
|---|---|
| Выручка, возвраты | `ledger_entries` (счета `provider:<имя>`, типы `payment` и `refund`), разрез `провайдер:тариф:валюта` |
| MRR, платящие | оплаченные счета (`MrrCalculator`), состояние на конец дня, разрез `тариф:валюта` |
| Регистрации | `users.created_at`, разрез источник (UTM или реферер или `direct`, из `user_attribution`) |
| Подтвердили почту, подключили канал, запланировали пост, активировались | `users.email_verified_at`, первый `channels`, первый не черновик `posts`, первая отправленная `publications` (по пространству) |
| Пробный период | `audit_log` `billing.trial_started` |
| DAU, WAU, MAU | `user_activity_days` (одна строка на человека и день, пишет `ActivityTracker` при входе в приложение; вход «под пользователем» не считается) |
| Публикации | `publications` с сетью из `post_variants.platform` |
| Визиты | `analytics_events` `visit` (одна на сессию, роботы не считаются) |

## Определения
- **MRR на момент `t`**: по каждому пространству берётся оплаченный счёт, период которого содержит `t` (при пересечении побеждает начавшийся позже); его `list_price` делится на число месяцев периода (год = 12). Счета с полностью возвращённым платежом не считаются; выданный без оплаты тариф не считается.
- **ARR** = MRR × 12. **Выручка** за период = платежи минус возвраты. **Платящие** = число пространств с MRR > 0 на конец периода.
- **Движение MRR** за день: новый (раньше не платил), расширение (MRR вырос), сокращение, отток (MRR стал 0). Смена валюты считается оттоком и новым.
- **Отток клиентов** = ушедшие за период / платящие на начало. **Отток выручки** = потерянный MRR / MRR на начало.
- **ARPU** = MRR / MAU; **ARPPU** = MRR / платящие; **LTV** = ARPPU / месячный отток клиентов (отток периода, приведённый к 30 дням); без оттока оценки нет.
- **Пробный → платный**: из пробных периодов, начатых в периоде, доля пространств, которые оплатили после начала пробного (когорта, не выше 100%).
- **Воронка**: визиты за период, затем люди, зарегистрировавшиеся в периоде, и сколько из них подтвердили почту, подключили канал, запланировали пост, оплатили (когда-либо).
- **Удержание**: неделя регистрации (строка), доля людей, вернувшихся на n-й неделе после своего дня регистрации.
- **Успешность публикаций** = вышло / (вышло + не вышло + неизвестно).

## Пересчёт
Каждый час планировщик пересчитывает 3 последних дня: день стирается и пишется заново в одной транзакции, поэтому повторный запуск ничего не меняет. `MetricsAggregator::range()` строит любой период (демо-данные, исправление истории). Дашборд при пустых данных показывает подсказку «Пересчитать цифры» (`POST /admin/dashboard/refresh`).

## Проверка
Тест `MetricsTest` строит «эталонный месяц» (`tests/Support/MetricsFixture.php`: восемь пространств, продления, повышение, возврат, отток, пробные периоды, активность) с заранее известными ответами: MRR 3 600 ₽, ARR 43 200 ₽, выручка 14 250 ₽, отток 50%, конверсия пробного 66,7%, ARPPU 720 ₽, LTV 1 440 ₽ и т. д.
