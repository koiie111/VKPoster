# TikTok Direct Post

Флаг `tiktok` в `PLATFORMS_ENABLED` и переключатель `/admin/platforms` управляют доступностью. OAuth Login Kit Web запрашивает `user.info.basic`, `video.publish`, `video.list`; callback одноразово проверяет `state` и право на подключение канала. В текущей [документации Login Kit](https://developers.tiktok.com/docs/en/login-kit-overview) PKCE указан для native/desktop, а не Web. `TikTokConnections` кладёт access/refresh токены в `CredentialVault`; `OAuthRefresher` атомарно сохраняет вращающийся refresh token. Персональный аккаунт становится каналом.

Перед каждой публикацией `TikTokAdapter` вызывает `creator_info/query`, сверяет выбранную пользователем приватность и запреты комментариев/дуэтов/стежков. Приватность не выбирается автоматически; права на музыку подтверждаются в редакторе. Direct Post и `PULL_FROM_URL` используют подписанную ссылку на S3 через подтверждённый в TikTok префикс `TIKTOK_VERIFIED_URL_PREFIX`. Полученный `publish_id` сохраняется до опроса `status/fetch`. Отказ отдаёт понятное сообщение, успех фиксирует публичный ID при его наличии. Удаление и правка ролика через используемый API недоступны.

До аудита TikTok ограничивает доступную видимость: приложение и выбранная приватность должны соответствовать текущим правам платформы. Суточный лимит для конкретного автора меняется у TikTok; `spam_risk_too_many_posts` трактуется как отсрочка, но локальный счётчик не может гарантировать остаток стороннего лимита. Статистика доступна при праве `video.list` для публичного ID. См. [ADR 0027](../../adr/0027-short-video.md) и [короткие видео](short-video.md).
