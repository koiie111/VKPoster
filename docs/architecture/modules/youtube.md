# YouTube Shorts

Отдельный Google OAuth клиент (`YOUTUBE_CLIENT_ID/SECRET`) запрашивает `youtube.upload`, `youtube.readonly` и offline refresh token. Пользователь выбирает канал на странице Google; callback сохраняет токены через `CredentialVault` и привязывает канал. `OAuthRefresher` продлевает токен перед публикацией и при проверке здоровья.

`YouTubeAdapter` создаёт сессию `videos.insert` с заголовком, описанием, приватностью, признаком «для детей», категорией и тегами. После ответа `Location` зашифрованный URL хранится в `video_provider_sessions`. Части по 8 МиБ отправляются с `Content-Range`; перед повторной попыткой API запрашивает подтверждённое сервером смещение. Принятый ID переводит публикацию в `processing`; `videos.list` подтверждает окончание обработки или отказ. При неясном исходе `OutcomeVerifier` смотрит последние загрузки именно привязанного канала и ищет уникальную метку в тегах. Без однозначного результата публикация остаётся `unknown`.

Лимит проекта `videos.insert` учитывается в [short-video](short-video.md). После окончания обработки выбранная обложка отправляется через `thumbnails.set` (ошибка обложки записывается отдельно и не отменяет вышедший ролик). `videos.update` меняет заголовок и описание, `videos.delete` удаляет ролик; OAuth запрашивает также право `youtube.force-ssl`. Просмотры, лайки и комментарии читаются через `videos.list`; подписчики — через `channels.list`. YouTube определяет Shorts по форме и длительности, а не отдельным методом вставки.
