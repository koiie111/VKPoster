# Конвейер публикации

`PublicationScheduler` ставит созревшие публикации в очередь `publish`, а короткие видео — в `video`. `Publisher` захватывает Redis-замок и атомарно переводит `queued → sending`; отправка идёт через адаптер платформы. Временные ошибки повторяются с паузами, постоянные завершаются `failed`, а неизвестный исход останавливается в `unknown` до проверки. Для платформ с `OutcomeVerifier` сначала выполняется сверка с каналом. После успеха фиксируются внешний ID, ссылка, попытка, статус поста и уведомление. Долгие видео используют замок и worker timeout, рассчитанные на перекодирование и возобновляемую загрузку.

Для асинхронных сетей `sending → processing → sent|failed|unknown`. `video_provider_sessions` сохраняет данные операции до отправки байтов и до первого опроса; `VideoProcessingJob` и планировщик переживают сбой worker. Сеть с неясным результатом не получает повторную загрузку автоматически. Схема и ограничения — [short-video](short-video.md), интеграции — [TikTok](tiktok.md), [YouTube](youtube.md), [Instagram](instagram.md).
