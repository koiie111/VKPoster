**Как проверить руками:**
1. `git fetch && git checkout stage-03-auth-social && make up && make migrate seed css`
2. Сначала без ключей, на тестовом провайдере: добавьте в `.env` строку `DEV_OAUTH_FAKE=1` (я уже добавил её в ваш локальный `.env`), `docker compose up -d app`. Откройте http://localhost:8080/login, нажмите «Войти через Тестовый вход», на странице провайдера нажмите «Разрешить вход», на шаге «Почти готово» согласитесь и создайте аккаунт. Затем «Безопасность» → «Способы входа»: задайте пароль и почту, выйдите, войдите паролем.
3. Для живой проверки создайте приложения и впишите ключи **сами в `.env`** (в чат не присылайте): `VKID_CLIENT_ID` (`VKID_CLIENT_SECRET` по желанию), `YANDEX_CLIENT_ID/SECRET`, `GOOGLE_CLIENT_ID/SECRET`, `TELEGRAM_LOGIN_BOT_TOKEN`, `TELEGRAM_LOGIN_BOT_NAME` (имя бота без @). Redirect URI везде: `<APP_URL>/auth/vkid/callback`, `/auth/yandex/callback`, `/auth/google/callback`. Для Telegram в @BotFather выполните `/setdomain` и укажите домен.
4. VK ID, Telegram и Google не работают с `http://localhost:8080`, нужен публичный HTTPS. Поднимите туннель: `docker compose --profile tunnel up -d tunnel`, затем `docker compose logs tunnel | grep trycloudflare` (там адрес вида `https://….trycloudflare.com`). Впишите его в `.env` как `APP_URL=…` (без слэша в конце), выполните `docker compose up -d app` и откройте сайт по этому адресу. Адрес меняется при каждом запуске туннеля, поэтому redirect URI и домен бота придётся обновлять; если есть постоянный домен, используйте его.
5. Проверьте вход каждым способом, затем привяжите второй способ в «Безопасность» → «Способы входа», выйдите и войдите вторым. Проверьте, что единственный способ отвязать нельзя.
