# Этап 04 — Workspace, команда, роли, аудит

**Зависимости:** 02 · **Ветка:** `stage-04-workspaces`

## Цель
Мультиарендность: все данные принадлежат workspace; доступ определяется ролью участника.

## БД
`workspaces`, `workspace_members`, `invitations`, `audit_log`.

## Задачи
- [x] При регистрации создаётся личный workspace (owner).
- [x] Переключатель workspace в шапке; текущий workspace в URL (`/w/{workspaceId}/...`) — middleware `ResolveWorkspace` проверяет членство (не член → 404).
- [x] Роли и права (матрица в `config/permissions.php`):
  | Право | owner | admin | editor | author | viewer | client |
  |---|---|---|---|---|---|---|
  | биллинг, удаление workspace | ✓ | | | | | |
  | участники, каналы | ✓ | ✓ | | | | |
  | публиковать и планировать | ✓ | ✓ | ✓ | | | |
  | создавать черновики, отправлять на согласование | ✓ | ✓ | ✓ | ✓ | | |
  | смотреть календарь и аналитику | ✓ | ✓ | ✓ | ✓ | ✓ | (только назначенное) |
- [x] `Policy`-классы + `Authorize` middleware + хелпер `can()` в Twig.
- [x] Базовый `WorkspaceScopedRepository`: метод без `WorkspaceContext` нельзя вызвать (проверка на уровне типа).
- [x] Приглашения по email (токен-хэш, TTL 7 дней, принятие → вход/регистрация → членство), отзыв приглашения, смена роли, исключение участника, выход из workspace, передача владения.
- [x] Ограничение доступа участника конкретными каналами (как в ecotime: «права на публикацию без админства в сообществе»): `member_channel_access` (таблица, репозиторий и тесты готовы; экран назначения каналов появится вместе с каналами, этап 06).
- [x] `AuditLogger`: события входа, смены ролей, подключения каналов, публикаций, биллинга; страница журнала для owner/admin с фильтрами (события входа остаются в личном журнале «Безопасность»; подключения каналов, публикации и биллинг запишут свои события в этапах 06–10).
- [x] Настройки workspace: название, часовой пояс, язык по умолчанию.

## Тесты
Матрица прав (data provider по всем ролям × действиям); IDOR: пользователь A не видит workspace B ни по одному маршруту (общий тест, который обходит все зарегистрированные маршруты `/w/{id}/…` с чужим id и ожидает 404); приглашение чужим токеном, истёкшее, повторное; нельзя понизить последнего owner.

## Проверка владельцем
Не требуется.

## DoD
