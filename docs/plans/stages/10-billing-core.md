# Этап 10 — Биллинг: тарифы, лимиты, ЮKassa, Т-Банк

**Зависимости:** 07 · **Ветка:** `stage-10-billing-core`

## Цель
Можно брать деньги: тарифы с лимитами, пробный период, оплата и автопродление через ЮKassa и интернет-эквайринг Т-Банка, чеки 54-ФЗ.

## БД
`plans`, `plan_prices` (период × валюта), `subscriptions`, `invoices`, `payments`, `payment_methods`, `webhook_events` (UNIQUE(provider, event_id)), `ledger_accounts`, `ledger_entries`, `usage_counters`.

## Задачи
- [ ] Тарифы и лимиты из мастер-плана §3.1 в `config/plans.php` + сид в БД (чтобы менять цены из админки без деплоя).
- [ ] `Entitlements`: единая точка «можно ли» (`canAddChannel`, `postsLeftThisMonth`, `hasFeature('approvals')`, …); middleware `PlanFeature`; проверка лимитов в сервисах (не только в UI). Понятные сообщения с кнопкой «Перейти на тариф».
- [ ] Подписка: trial 14 дней Pro при регистрации → по окончании Free; апгрейд (сразу, с доплатой пропорционально остатку), даунгрейд (с конца периода), отмена автопродления, возобновление. При переходе на Free лишние каналы ставятся на паузу, а не удаляются.
- [ ] Интерфейс `PaymentGateway`: `createPayment(Invoice, returnUrl, savePaymentMethod)`, `chargeSaved(Invoice, PaymentMethod)`, `refund(Payment, amount)`, `parseWebhook(Request): WebhookEvent` (с проверкой подлинности), `fetchStatus(paymentId)`.
- [ ] **ЮKassa** (официальный SDK): платёж с `save_payment_method`, редирект на страницу оплаты, вебхук (проверка IP из списка ЮKassa + повторный `GET /payments/{id}`), автоплатежи по `payment_method_id`, чек (`receipt` с `vat_code` и `payment_subject=service`), возврат.
- [ ] **Т-Банк интернет-эквайринг** (API v2): `Init` (с `Recurrent=Y`, `CustomerKey`, `Receipt`), подпись `Token` = SHA-256 от отсортированных значений с `Password`, нотификации (проверка `Token`, ответ `OK`), `Charge` по `RebillId`, `GetState`, `Cancel`.
- [ ] Продление: задача ежедневно находит подписки, заканчивающиеся через ≤ 3 дня, создаёт счёт, списывает сохранённым способом; при неудаче повторяет на 1 и 3 день и шлёт письма; по истечении — grace 3 дня, затем Free.
- [ ] Счета и квитанции в кабинете (история платежей, скачивание PDF-квитанции).
- [ ] Ledger (двойная запись) для внутреннего баланса: пока только записи об оплатах; баланс = сумма проводок.
- [ ] Fake-шлюз для тестов и local (страница «оплатить / отклонить»).
- [ ] Страница «Тарифы» в кабинете и сравнение тарифов.

## Тесты
Подделанный вебхук → отказ без изменений; повторный вебхук → одна обработка; гонка двух вебхуков; сумма в вебхуке не совпадает со счётом → отказ и алерт; апгрейд и даунгрейд с проверкой сумм; неудачное продление → повторы → Free; лимиты: 3-й канал на Free → отказ на уровне сервиса.

## Проверка владельцем
1. Завести тестовые магазины ЮKassa (тестовый `shopId` и ключ) и Т-Банка (тестовый терминал), вписать в `.env`; вебхуки направить через туннель (агент даст URL).
2. Оплатить тестовой картой Про на месяц через каждую платёжку, затем дождаться или принудительно запустить продление (`bin/console billing:renew --force <subscription>`). Всё прошло, чек сформирован?
3. Подтвердить цены и лимиты тарифов (или прислать свои).

## DoD
Обе платёжки проходят тестовые оплаты и рекуррентные списания у владельца.
