# Этап 21 — Дизайн-система и UX-основа

**Зависимости:** 01 · **Ветка:** `stage-21-design-system`
**Место в очереди:** сразу после этапа 01, до первых пользовательских экранов (см. таблицу в PROGRESS.md).

## Цель
Единый, дружелюбный и понятный интерфейс: каждый следующий экран собирается из готовых компонентов, а не верстается заново. Направление утверждает владелец до того, как пишется код компонентов.

## Ориентиры
Дружелюбный SaaS в духе Buffer и Later: светлый фон, много воздуха, мягкие скругления (8–12 px), один основной акцентный цвет + цвета соцсетей как вторичные метки, лёгкие тени, иллюстрации или иконки в пустых состояниях, понятная типографика. Тёмная тема — полноценная, не «инверсия».

## Часть A — направление (до кода компонентов, с вопросом владельцу)
- [ ] Изучить 5–7 референсов (Buffer, Later, Hootsuite, SMMplanner, ecotime, Publer, Metricool): что хорошо в редакторе, календаре и онбординге; краткий вывод в `docs/design/references.md` (только выводы и собственные схемы, без копирования чужих материалов).
- [ ] Подготовить **3 варианта стиля** в виде статичных HTML-страниц (`docs/design/directions/{a,b,c}.html`, Tailwind из сборки): палитра, шрифт, кнопки, поля, карточка поста, фрагмент календаря, пустое состояние; в светлой и тёмной теме.
- [ ] Снять скриншоты вариантов (`make ui-snap`) в `storage/ui-review/stage-21/` и задать владельцу вопрос: какой вариант, что поменять.
- [ ] Статус `NEEDS_OWNER` до выбора направления.

## Часть B — дизайн-система (после выбора)
- [ ] **Сборка CSS:** Tailwind CSS standalone CLI (бинарник фиксированной версии, проверка SHA-256 при сборке образа, без Node) → `resources/css/app.css` → `public/assets/build/app.[hash].css`; `make css`, `make css-watch`; сборка CSS в prod-образе и в CI (проверка, что собранный файл не устарел).
- [ ] **Токены** в `tailwind.config.js` / CSS-переменных: цвета (primary, нейтральные, success/warning/danger/info, цвета платформ VK/TG/MAX/IG), типографическая шкала, отступы (шаг 4 px), радиусы, тени, z-index, длительности анимаций. Светлая и тёмная тема через `data-theme` + `prefers-color-scheme`, переключатель в профиле.
- [ ] **Шрифт и иконки:** Inter (или выбранный, лицензия OFL) self-hosted в `public/assets/fonts` (без Google Fonts — CSP и 152-ФЗ); иконки Lucide (ISC) как SVG-спрайт.
- [ ] **Компоненты Twig** (`templates/components/`, вызов через `{% include %}`/макросы с явными параметрами): button (варианты, размеры, состояние загрузки), icon-button, input, textarea со счётчиком символов, select, checkbox, radio, switch, date-time picker (с часовым поясом), file dropzone, form-field (label, подсказка, ошибка), card, badge и status-badge (статусы постов и каналов), platform-badge, avatar, dropdown-menu, modal, drawer, tabs, toast, alert, tooltip, table (сортировка, пустое состояние, пагинация), pagination, empty-state (иллюстрация + текст + действие), skeleton, progress, stepper (онбординг), breadcrumbs, page-header, sidebar-nav, topbar с переключателем workspace, confirm-dialog для опасных действий.
- [ ] Поведение — Alpine.js (меню, модалки, вкладки) и htmx (частичная перезагрузка), без inline-скриптов (CSP с nonce), всё доступно с клавиатуры, фокус виден, `aria-*` у интерактивных элементов.
- [ ] **Макеты страниц:** layout приложения (сайдбар + топбар, на мобильном — нижняя навигация или бургер), layout авторизации, layout лендинга, layout админки.
- [ ] **Витрина** `/dev/ui` (только `APP_ENV=local`): все компоненты во всех состояниях и обеих темах — это и документация, и эталон для визуальной проверки.
- [ ] **Кликабельные прототипы ключевых экранов** на статичных данных (через компоненты): онбординг, список каналов, **редактор поста с превью под каждую соцсеть**, **календарь** (месяц, неделя, список), дашборд пользователя. Эти прототипы — эталон для этапов 02–11.
- [ ] **UX-тексты:** `docs/design/ux-writing.md` — тон (дружелюбный, на «вы», без канцелярита), шаблоны ошибок («что случилось → что сделать»), подтверждения, пустые состояния, кнопки (глагол + объект: «Запланировать пост»).
- [ ] **Инструмент визуальной проверки:** `tools/ui-snap/` — Playwright в отдельном docker-контейнере (профиль `tools`, Node только внутри этого контейнера, не в приложении): список URL этапа → скриншоты 375 / 768 / 1440 px × светлая и тёмная тема → `storage/ui-review/stage-NN/`; авто-проверка доступности axe-core (ошибки уровня serious/critical валят проверку); `make ui-snap STAGE=NN`, `make a11y`.
- [ ] Документация: `docs/design/design-system.md` (токены, компоненты, когда какой использовать, примеры кода).

## Тесты
- Рендер каждого компонента (Twig) без ошибок со всеми параметрами; экранирование пользовательского текста в компонентах (XSS-тест).
- `make a11y` по витрине и прототипам: 0 нарушений serious/critical, контраст WCAG AA в обеих темах.
- Нет горизонтального скролла на 360 px ни на одной странице витрины.
