# Этап 22 — Короткие видео: TikTok, YouTube Shorts, Instagram Reels, VK Клипы

**Зависимости:** 05, 07, 08, 10, 12 (или `SKIPPED`: тогда без Reels), 15 (статистика видео) · **Ветка:** `stage-22-short-video`

Будущая функция: одно вертикальное видео публикуется по расписанию сразу в несколько сетей коротких видео. Сейчас видео уже можно приложить к посту в Telegram, VK и MAX; здесь появляется отдельный тип поста «Короткое видео» со своими требованиями, обложкой и асинхронной обработкой на стороне сетей.

## Перед стартом (вопросы владельцу — задать в начале этапа и ждать ответа)
1. **Какие сети делаем.** У каждой свой риск в РФ, решение за владельцем:
   - **TikTok:** с 2022 года TikTok ограничивает загрузку нового контента для российских аккаунтов; Content Posting API требует аудита приложения, до аудита посты публикуются только как приватные. Делать ли модуль (за флагом), и для кого (клиенты с аккаунтами вне РФ)?
   - **YouTube Shorts:** YouTube в РФ замедлен; проект Google Cloud без аудита загружает видео только как приватные; квота YouTube Data API ограничена (загрузка видео — одна из самых дорогих операций). Делать ли модуль, подавать ли проект на аудит и увеличение квоты?
   - **Instagram Reels:** часть этапа 12 (Meta признана в РФ экстремистской организацией); здесь только общий интерфейс коротких видео, если этап 12 не пропущен.
   - **VK Клипы:** без юридических рисков, делаем в любом случае.
2. **Тарифы:** входит ли функция во все тарифы или с «Про»; лимиты (видео в месяц, размер файла, место в медиатеке).
3. **Предельный размер и длительность** загружаемого видео (предложение: до 1 ГБ и до 3 минут; больше — только по ссылке на файл в S3).

## Задачи
- [ ] **Исследование и ADR** `docs/adr/NNNN-short-video.md`: перед кодом сверить с актуальной документацией каждой сети способ авторизации, права, загрузку, ограничения и квоты (всё ниже — на момент написания плана, могло измениться):
  - TikTok: Login Kit (OAuth 2.0, access-токен ~24 ч, refresh ~365 дней), Content Posting API — `POST /v2/post/publish/creator_info/query/` (обязателен перед каждой публикацией: доступные уровни приватности, максимальная длительность, запреты комментариев, дуэтов и стежков), Direct Post (`video.publish`) или загрузка в черновики (`video.upload`, пользователь завершает публикацию в приложении), загрузка `FILE_UPLOAD` частями или `PULL_FROM_URL` (только с подтверждённого домена), статус через `/v2/post/publish/status/fetch/`; требования TikTok к интерфейсу (без значения приватности по умолчанию, согласие с правилами музыки, отметка коммерческого контента).
  - YouTube: Google OAuth с `offline`-доступом и правом `youtube.upload` (+ `youtube.readonly` для выбора канала и статистики), `videos.insert` с возобновляемой загрузкой (resumable upload), обязательные поля (`title`, `privacyStatus`, `selfDeclaredMadeForKids`), отложенная публикация самим YouTube (`status.publishAt`) против публикации в момент времени нашим планировщиком, обложка `thumbnails.set`, стоимость в единицах квоты и как её считать. Shorts определяется автоматически по вертикальному или квадратному формату и длительности (на 2024 год до 3 минут).
  - VK Клипы: методы публикации клипа от имени сообщества (раздел `shortVideo` или `video.save` с признаком клипа), какие права и какой токен нужны, работает ли с токеном VK ID из этапа 08, лимиты длительности и размера, обложка.
  - Instagram Reels (если этап 12 сделан): `media_type=REELS`, `share_to_feed`, `cover_url`/`thumb_offset`, ожидание `status_code=FINISHED`, лимит публикаций.
- [ ] **Тип поста «Короткое видео»** (`posts.kind = short_video` или отдельный флаг варианта): ровно одно видео; общие поля (описание, хэштеги) и вариант под каждую сеть: заголовок (YouTube, обязателен), приватность (TikTok, YouTube), разрешить комментарии / дуэты / стежки (TikTok), «для детей» (YouTube, обязательно), категория и теги (YouTube), «показать в ленте» (Reels), отметка рекламы / коммерческого контента, обложка. Поля и ограничения приходят из `Capabilities` адаптера, а не из шаблона.
- [ ] **Медиа для коротких видео** (расширение этапа 05):
  - загрузка больших файлов частями с возобновлением (resumable/chunked, проверка SHA-256 после сборки, лимит из тарифа), прогресс в интерфейсе;
  - `ffprobe`-проверка под каждую сеть: формат 9:16 (и допустимые 1:1/4:5 где можно), разрешение, длительность, частота кадров, кодек, размер; требования в `config/media.php → platforms`, проверка через `PlatformRequirements`;
  - профиль перекодирования в `ffmpeg` (H.264 + AAC, `+faststart`, без метаданных), когда исходник не подходит сети; выполняется в отдельной очереди `video` с ограничением параллельности, результат кэшируется как вариант (`VariantService`);
  - обложка: выбор кадра ползунком (кадр снимается `ffmpeg` на сервере) или своя картинка; превью 9:16 в редакторе и в медиатеке;
  - подписанные ссылки с TTL для сетей, которые забирают файл по URL (Reels, TikTok `PULL_FROM_URL`), — только через `MediaUrls::signed()` и S3.
- [ ] **Конвейер публикации для долгих загрузок:**
  - загрузка видео идёт в очереди `video` с увеличенным таймаутом, чтобы не задерживать обычные посты в очереди `publish`; возобновление загрузки после падения воркера (сохраняем upload-сессию сети, а не начинаем заново);
  - асинхронная обработка на стороне сети: новое промежуточное состояние публикации «обрабатывается сетью» (через `PublicationSystem::move`), опрос статуса с backoff и общим пределом времени, затем `published` или ошибка с понятным текстом;
  - защита от дублей: у YouTube нет ключа идемпотентности, при неизвестном исходе сверка через список последних загрузок канала (`OutcomeVerifier`), без автоповтора;
  - учёт квот: суточная квота YouTube на проект и лимиты TikTok/Instagram проверяются при планировании (как `Capabilities::$maxPostsPerDay`), остаток квоты виден в админке; при исчерпании публикация откладывается, а не падает.
- [ ] **Адаптеры** в `src/Integrations/Social/` (каждый за флагом `PLATFORMS_ENABLED`, свой API-клиент без SDK, токены только через `CredentialVault`, обновление через `OAuthRefresher`):
  - `TikTok/`: подключение аккаунта (OAuth, PKCE), проверка здоровья (токен жив, `creator_info` отвечает), публикация, статус, удаление невозможно через API → `Capabilities` отражает это;
  - `YouTube/`: подключение через Google OAuth (отдельно от входа через Google из этапа 03), выбор канала, публикация, обложка, удаление (`videos.delete`), правка заголовка и описания;
  - `Vk/`: клипы как ещё одна возможность существующего `VkAdapter` (тот же канал-сообщество);
  - `Instagram/`: Reels через общий интерфейс коротких видео (если этап 12 сделан).
- [ ] **Статистика** (`StatsFetcher` из этапа 15): просмотры, лайки, комментарии, репосты по видео; для YouTube и TikTok — с учётом квот и редких опросов.
- [ ] **Тарифы** (этап 10): возможность `short_video` в `PlanFeature`, лимиты видео в месяц и размера файла в `Entitlements`, баннер «Это ограничение тарифа».
- [ ] **Админка и метрики** (ENGINEERING_RULES §7): события `Analytics::track` (видео загружено, опубликовано, ошибка), агрегаты в `MetricsAggregator`, в операционной статистике — публикации видео по сетям, время обработки сетью p50/p95, остаток квот, очередь `video`; выключатели новых сетей в «Настройках сайта».
- [ ] **Интерфейс:** вкладка «Короткое видео» в редакторе, превью под каждую сеть (рамка 9:16 с подписью и элементами интерфейса сети), значок типа поста в календаре; новые экраны в `tools/ui-snap/urls/stage-22.json`.
- [ ] **Документация:** `docs/architecture/modules/short-video.md` и модули `tiktok.md`, `youtube.md`, дополнения в `vk.md`, `instagram.md`, `media.md`, `publishing.md`; схема БД; новые переменные (`TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`, `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`, лимиты видео) в `.env.example` и `configuration.md`; статьи справки «Как подключить TikTok / YouTube» и «Как запланировать короткое видео»; лендинг (если владелец решит рекламировать).

## Тесты
- Фейковые HTTP-ответы каждой сети (фикстуры): успешная загрузка частями, обрыв и возобновление, обработка дольше предела, ошибка обработки, исчерпанная квота, приватный режим до аудита (TikTok `SELF_ONLY`, YouTube `private`), истёкший токен и обновление.
- Проверка требований к видео: неподходящий формат, слишком длинное, слишком большое, перекодирование даёт годный файл (маленький тестовый ролик в `tests/fixtures`).
- Конвейер: видео не блокирует очередь `publish`, состояние «обрабатывается сетью» корректно переходит дальше, неизвестный исход не публикует дубль.
- Права и изоляция пространств для новых маршрутов, лимиты тарифа.
- Реальных запросов к API сетей в тестах нет.
