# Этап 23 — Источники контента, Радар, обработка материалов

**Зависимости:** 07 (посты и публикация), 10 (тарифы и лимиты), 20 (метрики и админка) · **Ветка:** `claude/adoring-meitner-uqd3zl` ([PR #20](https://github.com/koiie111/VKPoster/pull/20), продолжение PR #18)

Номер 22 занял этап «Короткие видео», поэтому «Источники» идут под номером 23. Владелец решил 2026-10-12, что функция нужна. Реализация пришла от внешнего разработчика в [PR #18](https://github.com/koiie111/VKPoster/pull/18) (ветка форка `stage-13-sources-skeleton`); доработка и merge идут в PR #20. Этот этап описывает, что должно войти в `main`, и закрывает замечания ревью этого PR. Если доработку ведёт автор PR, агент этот этап не начинает с нуля, а принимает его PR.

Термины: **источник** (Source) — откуда берём контент; **канал** (Channel) — куда публикуем. Это разные сущности.

## Задачи
- [x] **Источники**: отдельная сущность пространства (публичный Telegram-канал по `@username`), список, создание, правка, включение, статус подключения, права `sources.view|manage`, пункт меню (своя иконка, не как у «Каналов»), журнал аудита.
- [~] **Сервис чтения Telegram** (`tools/telegram-reader`, Python + Telethon, отдельный контейнер): чтение публичных каналов через MTProto, правки и альбомы, доставка событий во внутренний API (`/internal/source-events`, отдельный секрет `SOURCES_READER_SECRET`) с подтверждением после записи в БД, дедупликация. Продакшен-уровень: хранение и ротация сессии, мониторинг (heartbeat в `SystemStatus`), политика хранения локальных данных, работа при блокировке аккаунта (статус и баннер, а не тихая остановка). Тесты reader запускаются в CI (сделано, job `reader`). Не сделано до включения функции: шифрование тома сессии, мониторинг heartbeat в `SystemStatus`, баннер при блокировке аккаунта; функция выключена флагом `SOURCES_ENABLED=false` (ADR 0011).
- [x] **Отбор материалов**: детерминированные правила (включить, исключить, пересланные), ручное решение, смысловой AI-отбор по критериям пространства.
- [x] **Обработка**: текст (переписать, перевести), изображения (качество, поиск лучшей копии, улучшение), видео (генерация); у каждой операции история и ручной выбор версии.
- [x] **Радар трендов**: поиск тем вне подключённых источников, кластеры, объяснимая оценка, импорт в обработку.
- [x] **Черновики**: материал → обычный черновик поста в существующем редакторе; проверка актуальности материала перед публикацией (`ContentOriginGuard`) не меняет поведение обычных постов.
- [~] **Автоматизация**: по правилам пространства материал проходит отбор и обработку и становится черновиком. Автопубликации нет. Обработка разбита на задачи очереди по пространству, а не на один общий проход планировщика (`Automation::tick` ставит по задаче на пространство).
- [~] **Лимиты и деньги**: доступ к функциям по тарифу (`PlanFeature` / `Entitlements::assertFeature`), число источников по тарифу, платные вызовы (LLM, поиск и улучшение картинок, видео) учитываются по пространству (`usage_counters`, позже кредиты этапа 17); лимиты в Redis по пространству плюс общий потолок сервиса. Сделано: `ProviderQuota` (ИИ-кредиты тарифа `ai_credits`, лимит в минуту на пространство). Не сделано: доступ к функциям по тарифу (`PlanFeature`) и число источников по тарифу — зависит от ответа владельца на вопрос 4.
- [ ] **Провайдеры** за интерфейсами, по умолчанию Fake; Fake не работает в production. LLM-провайдер общий с этапом 17 (одна абстракция, а не две).
- [~] **Наведение порядка перед merge**: ADR сервиса чтения переименован в 0011 (сделано); миграции-исправления (`review_fixes`, `independent_review`) **оставлены отдельными**: на них опираются тесты на обновление схемы (`SourceMigrationTest`, `ReviewFixesTest`, `IndependentReviewTest`, `ContentDraftTest::tearDown`), а слияние вслепую рискованнее, чем два идемпотентных файла; имя миграции `000013` не менялось по той же причине; классы через `use`, а не полные имена в коде; README reader без локальных путей автора.
- [ ] Метрики, события и раздел админки (ENGINEERING_RULES §7).

- [ ] **Аккаунты Telegram для чтения** (решение владельца 2026-10-14, ADR 0012): несколько служебных аккаунтов сервиса, которыми управляет персонал в админке (добавить, отключить, статус, число источников на аккаунте, распределение источников, баннер и авто-перенос при блокировке); пользователь может подключить свой аккаунт (источники пространства читаются им, общий потолок сервиса не расходуется). Сессии только в зашифрованном виде.
- [ ] **Провайдеры OpenAI-совместимого формата**: один тип провайдера «OpenAI-compatible» с `base_url`, ключом и моделью (OpenAI, OpenRouter, YandexGPT/GigaChat через совместимые шлюзы, локальные модели и т. п.); несколько провайдеров настраиваются в админке (порядок, модель на операцию, включение), пользователь может указать свой ключ (BYOK, кредиты тарифа не списываются). Replicate и TinEye остаются отдельными адаптерами. SSRF-guard на `base_url`, ключи только зашифрованными.
- [ ] **Тарифы** (решение агента, утверждено владельцем «придумай сам»): Free — нет; Старт — `sources`, 3 источника, без Радара и автоматизации; Про — `sources`, `radar`, `source_automation`, 15 источников; Агентство — то же, 50 источников. Платные вызовы из `ai_credits`. Правки каталога в `config/billing.php` и миграция тарифов, лимит `sources` в `Entitlements`.
- [ ] **Авторские права**: в черновике хранится и показывается ссылка на источник (по умолчанию пометка включена, пользователь может снять); пункт в оферте «ответственность за публикацию переработанного контента на пользователе» (шаблон `resources/legal/offer.md`, на проверку юристу).

## Тесты
Изоляция пространств (чужой источник и материал → 404); права (роль без права → 403); CSRF; внутренний API без секрета или с неверным → 403/404; повторная доставка события не создаёт дубль; правка и удаление сообщения в Telegram делают черновик неактуальным, и публикация такого поста отказывается с понятной ошибкой; обычный пост публикуется как раньше; превышение тарифного лимита → отказ без вызова провайдера; Redis недоступен → платный вызов не идёт; миграции `migrate → rollback → migrate`; тесты reader в CI без реального Telegram.

## Проверка владельцем
Вопросы 1–4 решены 2026-10-14 (см. архив в PROGRESS.md и ADR 0012). Осталась живая проверка после реализации задач выше.

Исходные вопросы:
1. Авторские права: сервис берёт контент из чужих публичных каналов и переделывает его. Нужна ли пометка источника в черновике и пункт в оферте (ответственность за публикацию на пользователе)?
2. Аккаунт Telegram для чтения: один служебный аккаунт на весь сервис или несколько с распределением источников? Что показывать клиентам, если аккаунт заблокирован?
3. Провайдеры: в PR используются OpenAI, Replicate и TinEye (данные уходят за рубеж). Оставляем их или нужен российский LLM (YandexGPT/GigaChat), как в этапе 17? Нужен ADR.
4. На каких тарифах доступны «Источники», «Радар» и автоматизация, сколько источников и платных операций в месяц?
5. Живая проверка: подключить тестовый канал, дождаться материала, получить черновик и опубликовать его.
