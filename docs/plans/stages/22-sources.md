# Этап 22 — Источники контента, Радар, обработка материалов

**Зависимости:** 07 (посты и публикация), 10 (тарифы и лимиты), 20 (метрики и админка) · **Ветка:** `stage-22-sources`

Владелец решил 2026-10-12, что функция нужна. Реализация пришла от внешнего разработчика в [PR #18](https://github.com/koiie111/VKPoster/pull/18) (ветка форка `stage-13-sources-skeleton`). Этот этап описывает, что должно войти в `main`, и закрывает замечания ревью этого PR. Если доработку ведёт автор PR, агент этот этап не начинает с нуля, а принимает его PR.

Термины: **источник** (Source) — откуда берём контент; **канал** (Channel) — куда публикуем. Это разные сущности.

## Задачи
- [ ] **Источники**: отдельная сущность пространства (публичный Telegram-канал по `@username`), список, создание, правка, включение, статус подключения, права `sources.view|manage`, пункт меню (своя иконка, не как у «Каналов»), журнал аудита.
- [ ] **Сервис чтения Telegram** (`tools/telegram-reader`, Python + Telethon, отдельный контейнер): чтение публичных каналов через MTProto, правки и альбомы, доставка событий во внутренний API (`/internal/source-events`, отдельный секрет `SOURCES_READER_SECRET`) с подтверждением после записи в БД, дедупликация. Продакшен-уровень: хранение и ротация сессии, мониторинг (heartbeat в `SystemStatus`), политика хранения локальных данных, работа при блокировке аккаунта (статус и баннер, а не тихая остановка). Тесты reader запускаются в CI.
- [ ] **Отбор материалов**: детерминированные правила (включить, исключить, пересланные), ручное решение, смысловой AI-отбор по критериям пространства.
- [ ] **Обработка**: текст (переписать, перевести), изображения (качество, поиск лучшей копии, улучшение), видео (генерация); у каждой операции история и ручной выбор версии.
- [ ] **Радар трендов**: поиск тем вне подключённых источников, кластеры, объяснимая оценка, импорт в обработку.
- [ ] **Черновики**: материал → обычный черновик поста в существующем редакторе; проверка актуальности материала перед публикацией (`ContentOriginGuard`) не меняет поведение обычных постов.
- [ ] **Автоматизация**: по правилам пространства материал проходит отбор и обработку и становится черновиком. Автопубликации нет. Обработка разбита на задачи очереди по пространству, а не на один общий проход планировщика.
- [ ] **Лимиты и деньги**: доступ к функциям по тарифу (`PlanFeature` / `Entitlements::assertFeature`), число источников по тарифу, платные вызовы (LLM, поиск и улучшение картинок, видео) учитываются по пространству (`usage_counters`, позже кредиты этапа 17); лимиты в Redis по пространству плюс общий потолок сервиса.
- [ ] **Провайдеры** за интерфейсами, по умолчанию Fake; Fake не работает в production. LLM-провайдер общий с этапом 17 (одна абстракция, а не две).
- [ ] **Наведение порядка перед merge**: ADR сервиса чтения на свободный номер (0006 занят); миграции-исправления (`review_fixes`, `independent_review`) влиты в исходные; имена миграций идут после последней в `main`; классы через `use`, а не полные имена в коде; README reader без локальных путей автора.
- [ ] Метрики, события и раздел админки (ENGINEERING_RULES §7).

## Тесты
Изоляция пространств (чужой источник и материал → 404); права (роль без права → 403); CSRF; внутренний API без секрета или с неверным → 403/404; повторная доставка события не создаёт дубль; правка и удаление сообщения в Telegram делают черновик неактуальным, и публикация такого поста отказывается с понятной ошибкой; обычный пост публикуется как раньше; превышение тарифного лимита → отказ без вызова провайдера; Redis недоступен → платный вызов не идёт; миграции `migrate → rollback → migrate`; тесты reader в CI без реального Telegram.

## Проверка владельцем
Требуется.
1. Авторские права: сервис берёт контент из чужих публичных каналов и переделывает его. Нужна ли пометка источника в черновике и пункт в оферте (ответственность за публикацию на пользователе)?
2. Аккаунт Telegram для чтения: один служебный аккаунт на весь сервис или несколько с распределением источников? Что показывать клиентам, если аккаунт заблокирован?
3. Провайдеры: в PR используются OpenAI, Replicate и TinEye (данные уходят за рубеж). Оставляем их или нужен российский LLM (YandexGPT/GigaChat), как в этапе 17? Нужен ADR.
4. На каких тарифах доступны «Источники», «Радар» и автоматизация, сколько источников и платных операций в месяц?
5. Живая проверка: подключить тестовый канал, дождаться материала, получить черновик и опубликовать его.
