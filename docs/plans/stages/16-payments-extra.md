# Этап 16 — Остальные платёжки, рефералка, промокоды, пакеты

**Зависимости:** 10 · **Ветка:** `stage-16-payments-extra`

## Задачи
- [x] **CloudPayments**: виджет оплаты, проверка `Content-HMAC` (HMAC-SHA256 от тела, ключ API Secret) для уведомлений Check/Pay/Fail/Recurrent, рекуррентные подписки через API или токен карты, чеки (CloudKassir).
- [x] **Stripe** (свой HTTP-клиент вместо SDK, ADR 0015): Checkout Session в режиме `payment` с сохранением карты и продлением off-session вместо `subscription`, вебхуки (`Stripe-Signature`, допуск по времени 5 мин), перечитывание статуса из API. Customer Portal и `customer.subscription.*` не нужны при этой модели. Валюта USD/EUR, отдельные цены в `plan_prices`.
- [x] **Paddle Billing**: Paddle.js checkout, вебхуки (`Paddle-Signature`, HMAC-SHA256 `ts:body`), синхронизация подписки. Paddle — Merchant of Record (налоги на нём).
- [x] **Крипта**: провайдер выбирает владелец (варианты: CryptoCloud, Cryptomus, NOWPayments, Heleket — ADR по комиссиям, KYC, доступности); инвойс на сумму за период, вебхук с подписью, учёт недоплаты и переплаты, без автопродления.
- [x] **Telegram Stars**: оплата в боте уведомлений: `sendInvoice`/`createInvoiceLink` (`currency=XTR`, при возможности `subscription_period=2592000`), обработка `pre_checkout_query` (проверка счёта, ответ в течение 10 с), `successful_payment` → активация, `refundStarPayment` для возвратов. Цены в звёздах в `plan_prices`.
- [x] Выбор способа оплаты на странице тарифов: выбор валюты (₽ $ € ★) из валют включённых провайдеров, способы фильтруются по валюте (РФ → ЮKassa / Т-Банк / CloudPayments; иностранные карты → Stripe / Paddle; плюс крипта, Stars и реферальный баланс).
- [x] **Промокоды**: процент, сумма, бесплатные дни; ограничения (тарифы, первый платёж, лимит активаций, срок, один на пользователя); админка.
- [x] **Реферальная программа**: реф-ссылка (cookie 30 дней, атрибуция при регистрации), 20% с оплат приглашённых → ledger-баланс; оплата тарифа балансом; заявки на вывод для партнёров (ручная обработка в админке); защита от самоприглашения (тот же платёжный отпечаток, IP или устройство → отклонение).
- [x] **Пакеты**: +каналы, +участники, +хранилище, AI-кредиты (подготовка под этап 17) — как позиции счёта.

## Тесты
Подписи вебхуков каждого провайдера (валидная, невалидная, старый timestamp); идемпотентность; Stars: `pre_checkout_query` для несуществующего или чужого счёта → отказ; промокод сверх лимита; рефералка: самоприглашение, возврат платежа → сторно бонуса в ledger.

## Проверка владельцем
1. Какие провайдеры реально подключаем сейчас (для Stripe и Paddle нужно иностранное юрлицо; для крипты — выбор провайдера)? Вписать тестовые ключи.
2. Тестовая оплата через каждого подключённого провайдера. Ок?
3. Условия рефералки (20%, вывод) — подтвердить.

## DoD
Подключённые владельцем провайдеры проходят тестовые оплаты; остальные реализованы и покрыты тестами, но выключены флагами.

## Решение владельца (2026-10-18, чат)
Сервис делается для заказчика, поэтому всё настраивается через админку: включение провайдеров и ключи (`/admin/providers`), условия рефералки (`/admin/referrals`), промокоды (`/admin/promo`), пакеты (`/admin/addons`), цены в нескольких валютах (`/admin/plans`). Код реализует все провайдеры плана; какие из них включены, решает заказчик, остальные выключены.

## Перенесённые задачи и техдолг
- Живая проверка каждого провайдера (список в ADR 0015 «Что не проверено»): нужны тестовые ключи заказчика.
- Выбор крипто-провайдера: сделан Heleket с обоснованием в ADR; если заказчик выберет другого, меняется один класс `CryptoGateway`.
- Чек CloudKassir (54-ФЗ) не подключён: продавец на НПД выдаёт чеки сам; для другого налогового режима нужна отдельная задача.
- Реферальные бонусы начисляются только с рублёвых оплат; конвертация валют не делается (решение владельца, если понадобится).
- Продления Paddle, крипты, Stars и баланса вручную (особенность провайдеров); Customer Portal Stripe и подписки Telegram Stars не используются.
- Промокод даёт разовую скидку, повторяющиеся скидки на несколько периодов не делаются.
- Стоит добавить в `ui-snap` экраны `stage-16` (провайдеры, промокоды, пакеты, рефералы, приглашения): сейчас проверено вручную в браузере.
