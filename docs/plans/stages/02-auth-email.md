# Этап 02 — Регистрация и вход по email, 2FA, сессии

**Зависимости:** 01 · **Ветка:** `stage-02-auth-email`

## Цель
Нормальная собственная авторизация: регистрация, подтверждение email, вход, выход, сброс пароля, 2FA, управление сессиями.

## БД
`users`, `auth_tokens`, `user_sessions`, `recovery_codes`, `login_attempts` (или только Redis), `audit_log` (базово).

## Задачи
- [ ] Регистрация: email, пароль (≥ 10 символов, ≤ 128, не входит в топ-10k утёкших — словарь локально; опционально HIBP range API за флагом), имя, чекбокс согласия на обработку ПДн (с версией документа и датой в БД). Ответ одинаковый, существует email или нет (письмо «у вас уже есть аккаунт» на существующий).
- [ ] Письмо подтверждения (токен 32 байта, в БД SHA-256, TTL 24 ч, одноразовый). До подтверждения доступен только ограниченный интерфейс (middleware `RequireVerifiedEmail`).
- [ ] Вход: общая ошибка «неверный email или пароль»; защита от перебора: лимит по IP (20/10 мин) и по аккаунту (5 неудач → задержка с нарастанием, уведомление на email после 10); одинаковое время ответа (фиктивная проверка хэша для несуществующих).
- [ ] После входа: `session regenerate`, запись в `user_sessions` (хэш id, IP, UA), `password_needs_rehash`.
- [ ] «Запомнить меня»: отдельный токен selector:validator (validator хэшируется), 30 дней, ротация при использовании, отзыв при смене пароля.
- [ ] Выход (POST + CSRF), «выйти на всех устройствах».
- [ ] Сброс пароля: запрос (одинаковый ответ), токен TTL 1 ч, одноразовый, после смены — отзыв всех сессий и remember-токенов + письмо-уведомление.
- [ ] Смена email: подтверждение на новый адрес + уведомление на старый.
- [ ] Смена пароля (требует текущий пароль).
- [ ] 2FA TOTP: включение с QR-кодом (генерация QR на сервере в SVG, без внешних сервисов), подтверждение кодом, 10 recovery-кодов (показ один раз, хранятся хэшами), отключение по паролю + коду. Вход: шаг 2 с лимитом попыток, защита от повторного использования кода в том же окне.
- [ ] Страница «Безопасность»: активные сессии (устройство, IP, последняя активность) с отзывом, журнал последних входов.
- [ ] `DEV_LOGIN` (только `APP_ENV=local`): `/dev/login-as/{id}` для быстрого входа агентами и в smoke-тестах.
- [ ] Сид `user:create-admin` (суперадмин через CLI).
- [ ] Письма в Twig-шаблонах (HTML + текст), отправка через очередь, Mailpit в dev.

## Тесты
Feature: весь флоу регистрации → письмо в mail-фейке → подтверждение → вход → 2FA → выход; неверный пароль; блокировка после N попыток; повторное использование токена сброса → отказ; истёкший токен; токен чужого типа; remember-me ротация и кража (повторное использование старого validator → отзыв всех); отзыв сессии с другого устройства; CSRF на всех формах; `DEV_LOGIN` недоступен при `APP_ENV=production`.

## Проверка владельцем
1. Пройти в браузере: регистрация → письмо в Mailpit (http://localhost:8025) → вход → включить 2FA в Google Authenticator / Яндекс Ключ → выйти и войти с кодом. Всё понятно и работает?
2. Устраивают ли тексты и внешний вид страниц входа и регистрации? Что поменять?

## DoD
Флоу проходит руками и в тестах; чек-лист безопасности закрыт; ответы владельца получены.
