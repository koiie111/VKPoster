# Этап 02 — Регистрация и вход по email, 2FA, сессии

**Зависимости:** 01, 21 · **Ветка:** `stage-02-auth-email`

## Цель
Нормальная собственная авторизация: регистрация, подтверждение email, вход, выход, сброс пароля, 2FA, управление сессиями.

## БД
`users`, `auth_tokens`, `user_sessions`, `recovery_codes`, `login_attempts` (или только Redis), `audit_log` (базово).

## Задачи
- [x] Регистрация: email, пароль (≥ 10 символов, ≤ 128, не входит в топ-10k утёкших — словарь локально; опционально HIBP range API за флагом), имя, чекбокс согласия на обработку ПДн (с версией документа и датой в БД). Ответ одинаковый, существует email или нет (письмо «у вас уже есть аккаунт» на существующий).
- [x] Письмо подтверждения (токен 32 байта, в БД SHA-256, TTL 24 ч, одноразовый). До подтверждения доступен только ограниченный интерфейс (middleware `RequireVerifiedEmail`).
- [x] Вход: общая ошибка «неверный email или пароль»; защита от перебора: лимит по IP (20/10 мин) и по аккаунту (5 неудач → задержка с нарастанием, уведомление на email после 10); одинаковое время ответа (фиктивная проверка хэша для несуществующих).
- [x] После входа: `session regenerate`, запись в `user_sessions` (хэш id, IP, UA), `password_needs_rehash`.
- [x] «Запомнить меня»: отдельный токен selector:validator (validator хэшируется), 30 дней, ротация при использовании, отзыв при смене пароля.
- [x] Выход (POST + CSRF), «выйти на всех устройствах».
- [x] Сброс пароля: запрос (одинаковый ответ), токен TTL 1 ч, одноразовый, после смены — отзыв всех сессий и remember-токенов + письмо-уведомление.
- [x] Смена email: подтверждение на новый адрес + уведомление на старый.
- [x] Смена пароля (требует текущий пароль).
- [x] 2FA TOTP: включение с QR-кодом (генерация QR на сервере в SVG, без внешних сервисов), подтверждение кодом, 10 recovery-кодов (показ один раз, хранятся хэшами), отключение по паролю + коду. Вход: шаг 2 с лимитом попыток, защита от повторного использования кода в том же окне.
- [x] Страница «Безопасность»: активные сессии (устройство, IP, последняя активность) с отзывом, журнал последних входов.
- [x] `DEV_LOGIN` (только `APP_ENV=local`): `/dev/login-as/{id}` для быстрого входа агентами и в smoke-тестах.
- [x] Сид `user:create-admin` (суперадмин через CLI).
- [x] Письма в Twig-шаблонах (HTML + текст), отправка через очередь, Mailpit в dev.

## Тесты
Feature: весь флоу регистрации → письмо в mail-фейке → подтверждение → вход → 2FA → выход; неверный пароль; блокировка после N попыток; повторное использование токена сброса → отказ; истёкший токен; токен чужого типа; remember-me ротация и кража (повторное использование старого validator → отзыв всех); отзыв сессии с другого устройства; CSRF на всех формах; `DEV_LOGIN` недоступен при `APP_ENV=production`.
