## Цикл одного этапа

```
агент читает PROGRESS → берёт этап → ветка stage-NN → код + тесты в Docker → make check зелёный
   ├─ ручная проверка не нужна → PR → CI зелёный → squash-merge в main → STAGE_DONE → следующий этап
   └─ нужна ваша проверка → PR + вопросы в PROGRESS.md → NEEDS_OWNER (стоп, не мержит)
          вы проверяете и пишете ответы → снова запускаете агента → он доделывает и мержит
```

## Запуск

Автоматически, этапы подряд (по умолчанию максимум 3 за раз, останавливается на первом вопросе к вам):
```bash
scripts/agent-loop.sh
```

То же через Codex:
```bash
AGENT=codex scripts/agent-loop.sh
```

Один запуск вручную в Claude Code (интерактивно, можно наблюдать):
```bash
claude "$(cat docs/plans/AGENT_PROMPT.md)"
```

Один запуск вручную в Codex:
```bash
codex "$(cat docs/plans/AGENT_PROMPT.md)"
```

Права для безголового Claude заданы в `.claude/settings.json` (docker, make, git, gh разрешены; force-push, push в main и чтение `.env` запрещены). Если агент упирается в права, дополните список `allow`.

Codex запускается с `--full-auto` и сетью в песочнице. Проверьте флаги своей версии (`codex exec --help`) и при необходимости переопределите команду: `CODEX_CMD='...' AGENT=codex scripts/agent-loop.sh`.

## Когда агенту нужны вы
1. Придёт уведомление macOS (или скрипт напишет `NEEDS_OWNER`).
2. Откройте `docs/plans/PROGRESS.md` → «Вопросы владельцу». Там пошаговая инструкция, что проверить, и вопросы.
3. Ключи и токены вписывайте **только в `.env`** (агент назовёт переменные). Не пишите их в PROGRESS.md, PR или чат.
4. Впишите ответы после «Ответ владельца:», не переключая ветку git, и снова запустите `scripts/agent-loop.sh`.

Порядок этапов можно менять в таблице PROGRESS.md. Ненужный этап отметьте `SKIPPED`.
