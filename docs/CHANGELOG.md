### Added
- Этап 06: каналы и Telegram. Таблицы `channels`, `platform_credentials`, `channel_connect_codes` (внешний ключ у `member_channel_access`); контракты `Integrations/Social/Contracts` (`PlatformAdapter`, `ChannelConnector`, `Capabilities`, `PublishRequest`, `PublishResult`, `HealthStatus`, `PlatformError` с классами `temporary | permanent | auth | rate_limited | unknown_outcome`), `PlatformRegistry` и флаги `PLATFORMS_ENABLED`; свой клиент Telegram Bot API и `TelegramAdapter` (текст, фото, видео, документы, альбомы, опросы, кнопки, закрепление, удаление); подключение через общего бота по одноразовому коду (`/connect КОД`, вебхук `/webhooks/telegram/{secret}` с проверкой двух секретов) и через свой бот (токен шифруется `Crypto`, в интерфейсе только маска); проверка здоровья каналов (раз в 6 часов, по событию членства бота, вручную) с письмом владельцу и администраторам; экран «Каналы» (список, подключение с инструкцией и ожиданием в реальном времени, пауза, переименование, отключение), права `channels.view|manage`; тестовая сеть `fake`; команды `telegram:poll`, `telegram:webhook`, `channels:check`, `crypto:rotate`; ADR 0005; `docs/architecture/modules/channels.md`. Демо-каналы в сидере.
- Этап 05: медиатека. Таблицы `media`, `media_folders`, `watermarks`; хранилище за интерфейсом `MediaStorage` (Flysystem: локальный диск и S3/MinIO, `MEDIA_DISK`); загрузка с перетаскиванием, несколькими файлами и прогрессом, по ссылке (через SSRF-guard); тип по содержимому и белый список (jpeg, png, webp, gif, mp4, mov, pdf), защита от decompression bomb, пересборка изображений из пикселей (метаданные и спрятанные байты исчезают), превью, дедупликация по SHA-256, квота и лимит размера; видео через `ffprobe`/`ffmpeg` (в образ добавлен ffmpeg); варианты 1:1, 4:5, 1.91:1, 9:16 с кэшем; водяные знаки (положение 3×3, непрозрачность, размер, отступ, живой предпросмотр); раздача только через `/media/{id}/{variant}` (сессия или подписанная ссылка с TTL, `nosniff`, CSP `sandbox`, `Range`, `ETag`); папки, поиск, фильтр, страница файла с проверкой требований сетей; права `media.view|upload|manage`; события журнала; демо-данные в сидере; `docs/architecture/modules/media.md`.
- Этап 04: мультиарендность. Таблицы `workspaces`, `workspace_members`, `invitations`, `member_channel_access`; личное пространство при регистрации; маршруты `/w/{id}/…` с `ResolveWorkspace` (чужое пространство даёт 404) и `Authorize`; матрица прав `config/permissions.php` и шесть ролей; `WorkspaceScopedRepository` с правилом PHPStan; приглашения по почте (хэш токена, 7 дней, отзыв), смена ролей, исключение, выход, передача владения; ограничение доступа к каналам; журнал действий с фильтрами; настройки и удаление пространства; переключатель пространств; сквозной тест изоляции по всем маршрутам; `ui-snap` понимает `{ws}` в URL; `docs/architecture/modules/workspaces.md`.
- Этап 03: вход и регистрация через VK ID, Яндекс ID, Google (OIDC с проверкой подписи `id_token`) и Telegram Login Widget; PKCE, `state` и `nonce`; правила сопоставления аккаунтов (подтверждённая почта не склеивает аккаунты без пароля); отдельный шаг согласия на обработку ПДн; страница «Способы входа» (привязка, отвязка, запрет отвязать последний способ, первый пароль и почта для аккаунта из соцсети); 2FA после входа через соцсеть; тестовый провайдер `/dev/oauth/fake` (`DEV_OAUTH_FAKE`); таблица `user_identities`; CSP точечно расширяется на страницах с виджетом Telegram; ADR 0004; `docs/architecture/modules/social-auth.md`, `howto-oauth-provider.md`. ### Changed
- `Response` умеет отдавать тело из потока (`Response::stream`), `SecurityHeaders` не затирает CSP, который ответ принёс сам (так файлы пользователей отдаются с `sandbox`); компонент `progress` принимает `value_text`; в спрайт иконок добавлены `download`, `folder`, `folder-plus`.
- `/app` перенаправляет в рабочее пространство пользователя (`/w/{id}`); таблицы дизайн-системы получили `tabindex`/`role=region` для прокрутки с клавиатуры; `confirm_dialog` отправляет введённое название как `confirm_name`; `auth:prune` чистит и завершённые приглашения.
- Аккаунт без почты (создан через соцсеть) допускается в приложение без подтверждения почты; сброс 2FA и резервных кодов у аккаунта без пароля подтверждается кодом из приложения.
- `make init` пересоздаёт `APP_KEY`, если он не раскодируется в ровно 32 байта (раньше проверялась только длина строки).
- `Container::has()` больше не считает автосоздаваемыми классы без возможности создания (например, `Closure`); раньше это ломало автосборку `HttpClientInterface`.
- В тестах используется Redis db 15 (`REDIS_DB`), чтобы не затирать данные разработки.
- Layout приложения показывает демо-данные (рабочие пространства, тариф) только на прототипах; у вошедшего пользователя только существующие разделы.
- `make init` теперь определяет, что `APP_KEY` уже задан, по самому значению (раньше комментарий в строке `.env` считался значением).
- Образ PHP: добавлено расширение `pcntl`.
- `/healthz` и главная страница обслуживаются через `Application`; заглушки `bin/console` и `public/index.php` удалены.
- Название продукта: `ezposter` (`APP_NAME`).

### Removed
- Весь legacy-код (остался в теге `legacy-v0`), `vendor/` больше не коммитится.
