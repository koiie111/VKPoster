# 0007. Публикация в MAX: бот, свой клиент API, подключение по коду и по токену

- Статус: принято, требует живой проверки владельцем (см. «Что не проверено»)
- Дата: 2026-10-04

## Контекст
Этап 09 публикует в каналы и группы мессенджера MAX. Сведения взяты с `dev.max.ru` (разделы методов `POST /messages`, `POST /uploads`, `PUT/DELETE /messages`, `PUT/DELETE /chats/{id}/pin`, `GET /chats/{id}`, `GET /chats/{id}/members/me`, `POST /subscriptions`, `GET /updates`, объекты `Message` и `Update`), из публичных разборов и из клиента `max-bot-api-client-php`. Всё, что не удалось подтвердить по первоисточнику, помечено ниже.

## Что известно
- Базовый адрес `https://platform-api2.max.ru` (старый `platform-api.max.ru` отключается 19 июля 2026). Токен бота передаётся **только** заголовком `Authorization: <токен>` (без `Bearer`); токен в query-параметре больше не работает. Нужен российский корневой сертификат Минцифры в доверенных (в образе он есть: проверить на живом вызове).
- Ботов регистрируют только верифицированные юрлица РФ (кабинет `business.max.ru`).
- `POST /messages?chat_id=` (или `user_id=` для личного чата): тело `text` (до 4000 символов), `format` (`markdown` или `html`), `attachments`, `notify` (по умолчанию `true`; для каналов обязательно `true`), параметр `disable_link_preview`. Ответ: `{message: {body: {mid, ...}, url, recipient, ...}}`; `url` есть только у постов публичных каналов. Лимит: 2 сообщения в секунду на получателя.
- Файлы: `POST /uploads?type=image|video|file` даёт `{url, token?}`; файл отправляется на `url` multipart-полем `data`. Токен вложения у видео и файлов приходит сразу, у изображения после загрузки (`photos.<id>.token`). Вложение в сообщении: `{type, payload: {token}}`. После загрузки сообщение с этим файлом может получить ошибку «вложение ещё не обработано» (`attachment.not.ready`): документация советует повторять с растущими паузами. Лимиты: изображение 50 МБ, видео 250 МБ, файл 4 ГБ.
- Кнопки: вложение `inline_keyboard` с `payload.buttons` (строки кнопок), кнопка-ссылка `{type: "link", text, url}`.
- Редактирование `PUT /messages?message_id=` (`text`, `format`; если `attachments` не передан, вложения не меняются, пустой массив их удаляет), удаление `DELETE /messages?message_id=`, закрепление `PUT /chats/{id}/pin` (`message_id`, `notify`), снятие `DELETE /chats/{id}/pin` (у чата одно закреплённое сообщение). Редактирование, удаление и закрепление отвечают HTTP 200 и `{success, message}`: отказ приходит как `success: false`.
- `GET /chats/{id}` (`type`: `channel | chat | dialog`, `status`: `active | removed | left | closed`, `title`, `link`), `GET /chats/{id}/members/me` (`is_owner`, `is_admin`, `permissions`: `write`, `edit`, `delete`, `pin_message`, `read_all_messages`, …), `GET /chats/{link}` для публичных чатов.
- **Списка чатов, где состоит бот, нет:** `GET /chats` с июня 2026 не поддерживается, документация предлагает самим собирать `chat_id` из событий.
- События: webhook `POST /subscriptions` (только HTTPS, порт 443, секрет 5–256 символов `A-Za-z0-9-` приходит заголовком `X-Max-Bot-Api-Secret`, ответ 200 за 30 секунд, 10 повторов, через 8 часов без успеха подписка пропадает; старые подписки не заменяются новыми), либо `GET /updates` (long polling, для разработки). События `message_created`, `bot_added`, `bot_removed`, и др. В канале у сообщения нет `sender`. В событии нет идентификатора бота.

## Решение
1. **Свой клиент API**, без SDK: `MaxClient` (~15 методов), токен только в заголовке и только на `platform-api2.max.ru`; адрес загрузки файла (чужой хост MAX) получает файл **без** токена. Исключения транспорта не цепляются (токен в них не попадёт). Ошибки классифицируются так: 401 → `auth`; 403 → `auth`; 404 → `permanent` (канал не найден); 429 → `rate_limited`; 5xx → `temporary`; `attachment.not.ready` → `temporary` (внутри адаптера повторяется); `success: false` → `permanent`; остальное 400 → `permanent`. Оборванное соединение после отправки у публикующих вызовов → `unknown_outcome`, до соединения → `temporary`.
2. **Два режима, как в Telegram.** (а) Общий бот сервиса (`MAX_BOT_TOKEN`): человек добавляет бота администратором канала, получает одноразовый код на странице «Каналы» и пишет в канале `/connect КОД`; вебхук `/webhooks/max/{secret}` (путь + заголовок `X-Max-Bot-Api-Secret`, оба проверяются до чтения тела; заголовок выводится из секрета HMAC-ом). (б) Свой бот клиента: токен шифруется `CredentialVault`, канал указывается **ссылкой `max.ru/имя` или номером**, потому что без списка чатов бот сам не найдёт, куда его добавили. Приглашения `max.ru/join/…` не принимаются (по ним канал не найти).
3. **Права** выводятся из `members/me`: владелец может всё; администратор по списку `permissions` (`write` → публикация, `edit`, `delete`, `pin_message`; если списка нет, доверяем роли); в группе обычный участник может писать, в канале писать может только администратор. Подключение требует права публикации. `status` чата не `active` → канал «нужно переподключить».
4. **Отправка.** Один пост = одно сообщение: текст (`format: html`, разметка редактора превращается в `<b> <i> <s> <a>`), вложения по порядку, кнопки одним вложением `inline_keyboard` (каждая кнопка в своей строке, до 30). Файлы загружаются заранее; отправка с файлами повторяется при `attachment.not.ready` с паузами 1, 2, 4, 8, 15, 30 секунд (около минуты); «не готово» означает, что поста нет, поэтому повтор не создаёт дубль. Если пауз не хватило, ошибка `temporary` с повтором конвейера через 30 с. Лимит 2 сообщения в секунду на чат держит `MaxRateGate` (Redis, ключ из хэша токена и чата).
5. **Тихая отправка** (`notify=false`) каналы отвергают HTTP 400. Нужно ли отправлять тихо, адаптер не знает про тип чата, поэтому: пост уходит с `notify=false`, а если MAX отвечает 400 (пост точно не принят), он отправляется ещё раз без `notify=false`. Лучше громкий пост, чем потерянный.
6. **Оформление списков чатов отсутствует.** Страница подключения не предлагает «выбрать из списка»; она так и объясняет.
7. **Опросов в MAX нет** (`Capabilities::$polls = false`, `validate()` просит убрать опрос), **первого комментария нет**, **альбомов как отдельной сущности нет** (несколько вложений в одном сообщении).
8. **Правка опубликованного поста меняет только текст:** вложения остаются, потому что при передаче `attachments` MAX заменяет весь их список; кнопки на правке не обновляются.
9. Для разработки: `max:poll` (long polling; снимает подписки, чтобы события шли в опрос) и `max:webhook set|delete|info` (перед `set` удаляет старые подписки: MAX их не заменяет).

## Рассмотренные варианты
- **`BushlanovDev/max-bot-api-client-php`.** Вне белого списка зависимостей, ошибки не классифицируются под наш конвейер. Отклонено (как и SDK для VK).
- **Подключение без кода: «все чаты, где состоит бот» из `bot_added`.** Событие не говорит, чей это канал, а без кода любой, добавив бота, привязал бы чужой канал к своему пространству. Отклонено.
- **Регистрировать вебхук на каждого клиентского бота.** Нужны публичный HTTPS на каждого, свои секреты и подписки с 8-часовым отключением; для публикации не нужно. Отложено: свой бот публикует без входящих событий.

## Что не проверено (нужна живая проверка владельцем)
- Что общий бот получает сообщение `/connect КОД`, написанное в канале: для этого, возможно, нужно право «читать все сообщения» (`read_all_messages`); инструкция на странице это упоминает.
- Точный формат ответа загрузки изображения (`photos`), видео и файла и ошибки `attachment.not.ready` (код в теле и статус 400): адаптер принимает токен и из первого ответа, и из ответа файлового сервера, а «не готово» распознаёт по коду или по тексту.
- Как MAX разбирает HTML (`<s>`, переводы строк) и считает 4000 символов (с разметкой или без): адаптер считает видимые символы.
- Записывается ли ссылка публичного канала в `GET /chats/{link}` с `@` или без: адаптер пробует имя без `@`, затем с `@`.
- Принимает ли MAX `notify=false` в группах и как отвечает канал: есть откат на обычную отправку.
- Тип `chat_type` в событиях (`channel`, `chat`, `dialog`) и состав `sender`: выведены из документации объекта `Message`.
- Поле `permissions` у бота-администратора канала и название права «публиковать».

## Последствия
- Новых зависимостей нет; миграций нет (`platform_credentials` и `channels` уже подходят).
- Всё про MAX лежит в `src/Integrations/Social/Max`, `MaxUpdateHandler`, `MaxConnectController`; добавление сети не затронуло конвейер публикации.
- Пока владелец не завёл верифицированного бота, режим общего бота недоступен (страница это говорит), а живая проверка отложена.
