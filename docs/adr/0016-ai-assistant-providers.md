# 0016. ИИ-ассистент: провайдеры из коробки и OpenAI-совместимые модели

- Статус: принято, требует живой проверки владельцем (см. «Что не проверено»)
- Дата: 2026-10-18

## Контекст
Этап 17 (часть «ИИ»). План оставлял выбор провайдера владельцу; решение владельца (чат, 2026-10-18): сделать разных провайдеров «из коробки» и подключение любых OpenAI-совместимых моделей. Как и платёжные системы (ADR 0015), всё настраивается в админке. ADR 0012 уже требовал один интерфейс LLM, общий с «Источниками», OpenAI-совместимый адаптер, BYOK, SSRF-guard и шифрование ключей.

## Решения
1. **Интерфейс `LlmProvider::complete(LlmRequest): LlmResult`** (`src/Integrations/Ai/Llm`). Два протокола: `OpenAiCompatibleProvider` (`POST {base_url}/chat/completions`, ключ в `Authorization: Bearer` или `Api-Key`) и `AnthropicProvider` (родной Messages API Claude). Плюс `FakeLlmProvider`. Один класс для OpenAI-совместимых покрывает все пресеты: различаются только адрес, модель и способ передачи ключа.
2. **Пресеты (`LlmCatalog`)**: OpenAI, Anthropic, Google Gemini (совместимый адрес `…/v1beta/openai`), OpenRouter, YandexGPT (Yandex AI Studio, `Api-Key`; данные остаются в РФ), DeepSeek, Groq, Mistral, Together AI. Владельцу нужен только ключ (для Яндекса ещё модель с идентификатором каталога). Любой другой сервис добавляется как `custom-<имя>` с адресом, моделью, ключом и способом авторизации. Метка региона («данные остаются в РФ» / «уходят за рубеж») показывается в админке; в политику конфиденциальности это вносит владелец.
3. **Хранение как у платёжных провайдеров**: `ai_providers.config_enc` (JSON, `Crypto`), секрет не показывается повторно, пустое поле оставляет сохранённый, сохранение требует повторного кода 2FA (`StepUp`), право `ai.manage` у суперадмина, аудит без значений, `crypto:rotate` перешифровывает. Один провайдер «по умолчанию» (`is_default`); запасные включённые пока не используются автоматически (техдолг: маршрутизация по действиям и fallback).
4. **Своя модель пространства (BYOK)**: `ai_workspace_settings.byok_enc`. Запросы идут напрямую с ключом пользователя, **кредиты не списываются**, ключ владельца сервиса не используется. Менять может только владелец/администратор (`workspace.settings`).
5. **SSRF и транспорт**: адрес вводит человек, поэтому каждый вызов идёт через `SsrfGuard` (`user_url`): только публичный https (в форме требуем `https://`, без логина, параметров и фрагмента), порты 443/8443 и т. п. из белого списка, соединение закрепляется за проверенным IP, редиректы не выполняются, тело ответа ограничено 2 МБ, текст ошибки провайдера отбрасывается (он может повторить запрос или ключ), платный POST не повторяется. Следствие: **локальные модели (Ollama на localhost) напрямую не подключаются**; нужен публичный https-адрес или шлюз. Это сознательно (SSRF важнее удобства).
6. **Безопасность промпта**: системные правила пишем мы; текст поста, пожелания и голос бренда передаются как данные в `<material>`, `<brief>`, `<brand_voice>`, закрывающие теги внутри данных нейтрализуются, модели сказано не выполнять инструкции из данных. Ответ приходит как обычный текст: клиент показывает его через `textContent`, в шаблоны он не подставляется, обрамляющие ``` снимаются, длина ограничена. Из разметки разрешены только `**`, `*` и `[текст](https://…)` (грамматика редактора).
7. **Кредиты (`AiCredits`)**: цены действий: написать пост 3, переписать 2, остальные 1. Перед вызовом только проверка «хватает ли»; **списание после успешного ответа**: сначала месячный лимит тарифа (`usage_counters`, одно условное UPDATE), остаток из кошелька `wallet:CRD:…` (проводка `ai_spend`, идемпотентна). Ошибка модели, пустой ответ, таймаут ничего не списывают. Свой ключ и тестовая модель бесплатны. Гонка двух запросов на последние кредиты может на единицу превысить остаток (проверка до, списание после): сознательный компромисс против резервирования, провайдеру платим в любом случае.
8. **Лимит запросов**: `AI_WORKSPACE_PER_MINUTE` на пространство в Redis (при сбое Redis запрос отклоняется), плюс лимит маршрутов `RateLimit`.
9. **Логи**: `ai_usage` хранит только метрики (действие, провайдер, модель, токены, кредиты, статус, длительность); ни текстов постов, ни ответов, ни ключей в логах, аудите и аналитике нет (`ai_request` в `analytics_events` с действием и признаком «свой ключ»).
10. **Fake**: вне production без подключённого провайдера отвечает тестовая модель (`AI_FAKE=true` по умолчанию); в production «не подключено» с понятным сообщением.

## Не вошло в этот шаг
- GigaChat (Сбер): нужен OAuth с обменом ключа на токен и сертификат НУЦ Минцифры; пока доступен через OpenAI-совместимый шлюз (`custom-…`). Нативный адаптер: техдолг.
- ALT-текст для изображения (мультимодальность) и проверка орфографии отдельным сервисом (орфография сделана промптом).
- Маршрутизация по действиям, fallback между провайдерами, расчёт стоимости в деньгах по токенам.
- UTM и сокращатель ссылок (вторая половина этапа 17).

## Что не проверено (нужны ключи и живые вызовы владельца)
Все адаптеры проверены только на записанных по документации ответах: OpenAI, Anthropic, Gemini compat, OpenRouter, Yandex AI Studio (в частности формат названия модели `gpt://<каталог>/yandexgpt/latest` и приём `Api-Key` на `/v1/chat/completions`), DeepSeek, Groq, Mistral, Together.
