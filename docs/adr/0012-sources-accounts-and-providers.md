# 0012. Аккаунты Telegram и провайдеры для «Источников»

- Статус: принято (решение владельца, чат 2026-10-14); реализация в этапе 23
- Дата: 2026-10-14

## Контекст

Этап 23 читает публичные Telegram-каналы через MTProto-аккаунт и вызывает внешние ИИ-сервисы. Оставались открытыми: один общий аккаунт или несколько, какие провайдеры, на каких тарифах функция доступна.

## Решение

1. **Аккаунты чтения.** Несколько служебных аккаунтов сервиса, управляются персоналом в админке (разрешение `sources.accounts`, аудит, подтверждение кодом для добавления и удаления). Источники распределяются по аккаунтам; при блокировке аккаунт помечается, источники переносятся, клиент видит понятный статус, а не тихую остановку. Пользователь может подключить собственный аккаунт; тогда его источники читает он и общий потолок сервиса не тратится. Сессии хранятся зашифрованными (`Crypto`).
2. **Провайдеры.** Один интерфейс LLM, общий с этапом 17. Основной адаптер — OpenAI-совместимый (`base_url` + ключ + модель): подходит OpenAI, OpenRouter, российские шлюзы, локальные модели. Провайдеры и модели по операциям настраиваются в админке; пользователь может указать свой ключ (BYOK, кредиты не списываются). `base_url` проходит SSRF-guard, ключи шифруются, Fake в production запрещён. Replicate и TinEye остаются отдельными адаптерами; данные при этом уходят за рубеж, это указывается в политике конфиденциальности.
3. **Тарифы.** Free — нет; Старт — источники (3), ручной отбор; Про — 15 источников, Радар, автоматизация; Агентство — 50. Платные вызовы тратят `ai_credits`.
4. **Авторские права.** Ссылка на источник сохраняется в черновике, пометка по умолчанию включена; оферта возлагает ответственность за публикацию на пользователя (текст на проверку юристу).

## Последствия

Растёт объём админки и хранения секретов (сессии, ключи). Функция остаётся выключенной (`SOURCES_ENABLED=false`) до завершения этих задач и живой проверки.
