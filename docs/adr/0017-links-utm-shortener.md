# 0017. Ссылки в постах: UTM-метки и собственный сокращатель

- Статус: принято
- Дата: 2026-10-18

## Контекст
Этап 17 (часть «ссылки»). Нужны авто-UTM при публикации и сокращатель с подсчётом переходов. Решение владельца (чат, 2026-10-18): делать эту часть следующим запуском этапа. Новых зависимостей нет.

## Решения
1. **Где применяется.** В `PublishRequestBuilder::build`, одним шагом `LinkRewriter` до форматирования текста. Поэтому проверки в редакторе, счётчик знаков и публикация видят одни и те же адреса. Порядок: проверка чёрного списка → UTM → сокращение (короткая ссылка ведёт на адрес уже с метками).
2. **UTM.** Правило на пространство и необязательное переопределение на канал (наследовать / выключить / своё). Шаблоны с подстановками `{platform}`, `{channel}`, `{date}`, `{month}`; значения приводятся к `[a-z0-9_.-]` (кириллица транслитерируется). Метка, которая уже есть в адресе, не заменяется; якорь (`#…`) и остальные параметры остаются на месте. Ссылки находятся и в разметке `[текст](адрес)`, и «голые», и в кнопках. Первый комментарий пока не обрабатывается (техдолг).
3. **Сокращатель.** Код 7 символов base62 из `random_int` (62⁷ ≈ 3,5·10¹², перебор не имеет смысла, плюс лимит 120 запросов/мин на посетителя). Адрес: `https://<SHORT_LINK_DOMAIN>/<код>`, а если домен не задан, `APP_URL/s/<код>`; маршрут `/<код>` отвечает только на хосте короткого домена и регистрируется последним, чтобы не перекрыть настоящие страницы. Редирект 302 с `Cache-Control: no-store`, чтобы отключение действовало сразу. Для каждой пары «вариант поста × адрес» одна ссылка (повтор публикации берёт тот же код), у каждой соцсети своя ссылка, поэтому источник перехода известен без разбора Referer.
4. **Клики.** Строка в `short_link_clicks`: время, соль-хэш посетителя (`HMAC(ключ приложения, день|IP|User-Agent)`, усечён до 16 символов; меняется каждый день, по нему нельзя следить за человеком; сам IP не хранится) и признак робота (превью Telegram/VK/WhatsApp, краулеры). Счётчики `clicks` и `human_clicks` лежат на ссылке. Строки старше `SHORT_LINK_CLICK_RETENTION_DAYS` (400) удаляются планировщиком; счётчики остаются. Страна по GeoIP не делается (опционально по плану; нужна база и решение по лицензии; техдолг).
5. **Защита (`UrlGuard`).** Только `http`/`https`, без логина и пароля в адресе, без пробелов и управляющих символов, до 2000 знаков, без внутренних хостов (`localhost`, частные и зарезервированные IP, имена без точки, `.local`, `.internal`), не короткий домен самого сервиса. Чёрный список доменов (с поддоменами) ведёт суперадмин/поддержка в `/admin/links` (хранится в `app_settings`, `links.blocked_domains`). Список проверяется три раза: при создании короткой ссылки, при проверке и публикации поста (пост с запрещённым сайтом отклоняется, а не молча сокращается) и при каждом переходе (запрет «задним числом» действует сразу). При сохранении списка все существующие ссылки на эти домены отключаются. Отключать любую ссылку можно из админки; ссылку, закрытую поддержкой, владелец сам включить не может.
6. **Google Safe Browsing не подключаем сейчас.** Это внешний API с ключом и политикой хранения запросов; по плану он опционален. Вместо него ручной список. Подключение возможно за интерфейсом без изменений в остальном коде (техдолг; нужен ключ и решение владельца).
7. **Идентификаторы.** В URL интерфейса у ссылки публичный ULID (`short_links.public_id`), числовой id наружу не выходит. Ручные ссылки: не больше `SHORT_LINK_MANUAL_PER_DAY` (100) в сутки на пространство и лимит маршрута.

## Последствия
- Короткая ссылка короче исходной, но текст поста в соцсети содержит адрес нашего сервиса: если домен недоступен, ссылки в уже вышедших постах не работают. Домен нужно держать продлённым.
- Включённое сокращение меняет адреса только у ещё не вышедших постов.
