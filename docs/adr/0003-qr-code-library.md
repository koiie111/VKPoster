# 0003. Библиотека `bacon/bacon-qr-code` для QR-кода 2FA

- Статус: принято
- Дата: 2026-10-04

## Контекст
Этап 02: при включении двухфакторной аутентификации пользователь сканирует QR-код с адресом `otpauth://…`. План требует генерировать QR на сервере в SVG, без внешних сервисов (секрет не должен уходить третьей стороне). В белом списке ENGINEERING_RULES §2 есть `spomky-labs/otphp` для TOTP, но нет генератора QR.

## Решение
Добавить `bacon/bacon-qr-code` (v3, лицензия BSD-2-Clause) вместе с единственной зависимостью `dasprid/enum`. Используется только SVG-бэкенд (`SvgImageBackEnd`), поэтому расширение imagick не требуется. Генерация идёт на сервере, SVG отдаётся авторизованному пользователю с `Cache-Control: no-store`.

## Рассмотренные варианты
- **Написать свой кодировщик QR.** Reed-Solomon, маски, версии и форматная информация легко ломаются незаметно: неверный QR выглядит как рабочий, но не сканируется. Дорого проверять и поддерживать ради вспомогательной функции.
- **Внешний сервис (Google Charts и подобные).** Секрет 2FA ушёл бы третьей стороне, запрещено правилами.
- **JS-библиотека в браузере.** Секрет не покидает страницу, но добавляется скрипт и появляется зависимость от фронтенда; CSP остаётся строгой, но тестировать сложнее. Серверный вариант проще.

## Последствия
- Две новые зависимости (`bacon/bacon-qr-code`, `dasprid/enum`), обе под `composer audit`.
- Если проект перестанет поддерживаться, замена локальна: используется один класс `App\Domain\Auth\QrCode`.
