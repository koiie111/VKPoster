# 0010. Публикация в Instagram: Instagram Login, свой клиент, публичные ссылки на медиа

- Статус: принято, требует живой проверки владельцем (отложена по решению владельца 2026-10-14, см. «Что не проверено»)
- Дата: 2026-10-14

## Контекст
Этап 12. Meta признана в РФ экстремистской организацией, поэтому владелец выбрал вариант «б»: код есть, но сеть **выключена по умолчанию** (`PLATFORMS_ENABLED` без `instagram`) и включается только его флагом. Сведения о API взяты из документации Meta «Instagram API with Instagram Login», «Content Publishing» и «Long-lived access token» и не проверены живыми вызовами.

## Что известно
- Два пути: (а) Instagram API with Instagram Login (`graph.instagram.com`, вход на `www.instagram.com/oauth/authorize`) и (б) Facebook Login (страница Facebook, `graph.facebook.com`). Нужен Business- или Creator-аккаунт; права `instagram_business_basic`, `instagram_business_content_publish` (и `instagram_business_manage_comments` для первого комментария); для чужих аккаунтов нужен App Review.
- Авторизация: `code` обменивается `POST https://api.instagram.com/oauth/access_token` на краткоживущий токен (1 час) и `user_id`; `GET https://graph.instagram.com/access_token?grant_type=ig_exchange_token` меняет его на долгоживущий (около 60 дней). Долгоживущий токен продлевается `GET https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token`: токену должно быть не меньше 24 часов, и он не должен истечь. **Refresh-токена нет:** продлевается сам access-токен.
- Публикация в два шага: `POST /{ig-id}/media` создаёт контейнер (`image_url` или `video_url` — **публичная ссылка**, которую Meta скачивает сама; `caption`; `media_type` = `REELS` / `STORIES` / `CAROUSEL`; `is_carousel_item`; `children`; `share_to_feed`), `GET /{container}?fields=status_code` показывает `IN_PROGRESS`, `FINISHED`, `ERROR`, `EXPIRED`, `PUBLISHED`; готовый контейнер публикует `POST /{ig-id}/media_publish`. Фото только JPEG. Карусель до 10 элементов. Подпись до 2200 символов, до 30 хэштегов.
- Суточный лимит: `GET /{ig-id}/content_publishing_limit?fields=quota_usage,config` (на момент написания 100 публикаций за 24 часа на аккаунт, карусель считается за одну).
- Первый комментарий: `POST /{media-id}/comments`. Удаления и закрепления публикаций через API **нет**, редактирования подписи **нет**.
- Токен можно передавать заголовком `Authorization: Bearer …`.

## Решение
1. **Instagram Login (а), не Facebook Login.** Клиенту не нужна страница Facebook, меньше шагов, один токен на аккаунт. Минус: нужна Meta-приложение типа Business и App Review для чужих аккаунтов; для своих тестовых аккаунтов хватает режима разработки.
2. **Один аккаунт = один канал.** Вход Instagram даёт ровно один профессиональный аккаунт, поэтому шага «выберите сообщества», как у VK, нет: callback сразу создаёт канал. Режим канала `account`, `external_id` — `user_id` аккаунта Instagram.
3. **Свой клиент** (`InstagramApi`, ~6 методов), без SDK. Токен только в заголовке. Исключения транспорта не цепляются. Ошибки: код 190 (токен недействителен) и 10, 200–299 (права) → `auth`; 4, 17, 32, 613, 80002 и подкод 2207042 (суточный лимит) → `rate_limited`; 1, 2 и HTTP 5xx → `temporary`; остальное → `permanent`. Обрыв после отправки у `media_publish` → `unknown_outcome`; создание контейнера повторять безопасно (пока он не опубликован, поста нет).
4. **Продление токена без refresh-токена.** `OAuthRefresher` различает платформы по строке `platform_credentials`. Для Instagram запас до истечения 7 дней (а не 5 минут): проверка здоровья каналов раз в 6 часов и проверка перед публикацией продлевают токен задолго до конца. Блокировка Redis и ожидание параллельного воркера общие с VK. Если Instagram отказал (токен отозван или истёк), канал помечается «нужно переподключить».
5. **Публичные ссылки на медиа — через наше приложение, а не S3.** План предполагал S3 + подписанные ссылки. Но `MediaFileController` уже отдаёт `/media/{id}/{variant}` по подписи со сроком (`MediaUrls::signed`, `MEDIA_SIGNED_URL_TTL`), поэтому отдельное публичное хранилище не нужно: S3 остаётся вариантом хранения (`MEDIA_DISK=s3`), а наружу файлы выходят только через подписанную ссылку приложения. Требование: `APP_URL` должен быть публичным HTTPS-адресом (в разработке — туннель `cloudflared`, профиль `tunnel`). Ссылка живёт час: Meta скачивает файл сразу при создании контейнера.
6. **Картинки всегда JPEG.** Вариант картинки получил суффикс `-jpg` (`4x5-jpg`): это JPEG без прозрачности до 8 МБ. Конвейер подставляет подходящую обрезку, если соотношение сторон вне 4:5…1,91:1 (автокадрирование этапа 05), и `-jpg` всегда.
7. **Форматы.** Один ролик → Reels (по умолчанию, `share_to_feed=true`); фото и набор из 2–10 файлов → пост или карусель; «История» выбирается в настройках поста для Instagram (один файл). Кнопок, опросов, документов и закрепления нет; удаление и правка недоступны (`Capabilities`: `delete=false`, `pin=false`); первый комментарий есть.
8. **Ожидание контейнера:** опрос с нарастающими паузами 2, 3, 5, 8, 13, 20, 30 с (до 5 минут). Если не успел — `temporary` (поста ещё нет, повтор безопасен), `ERROR` и `EXPIRED` — `permanent`.
9. **Лимит до публикации:** `content_publishing_limit` проверяется перед созданием контейнеров; при исчерпании — `rate_limited` на час. Предупреждение в редакторе берёт `Capabilities::$maxPostsPerDay` (100, `INSTAGRAM_POSTS_PER_DAY`).
10. **Проверка неизвестного исхода** (`OutcomeVerifier`): последние 20 публикаций аккаунта, поиск по подписи и времени.

## Рассмотренные варианты
- **Facebook Login + страница Facebook** — больше прав и App Review, ненужная сущность для клиента. Отклонено.
- **S3 с публичными подписанными ссылками** — второй путь отдачи файлов и своё управление сроками. Отклонено (см. п. 5), остаётся возможным на будущее.
- **Расширение `ImageProcessor` без новых слагов** — ссылка должна однозначно описывать результат, поэтому формат в слаге.

## Что не проверено (нужна живая проверка владельцем)
- Весь поток OAuth и обмен токенов с реальным приложением Meta (App Review, режим разработки, тестовый Business-аккаунт).
- Что Meta скачивает файлы с нашей подписанной ссылки (заголовки, `Range`, срок ссылки), и что подписанная ссылка проходит через туннель или прокси.
- Фактический суточный лимит и формат ответа `content_publishing_limit`; что `quota_usage` считает карусель как одну публикацию.
- Поведение `REELS` с `share_to_feed`, требования Meta к видео (кодек, длительность, соотношение) и тексты ошибок контейнера.
- Продление токена: что токен моложе суток не продлевается, ответ на отозванный токен.
- Право `instagram_business_manage_comments` для первого комментария.
- Alt-текст: API принимает `alt_text` для фото, но в медиатеке нет поля описания, поэтому он не отправляется (задача в техдолге).

## Последствия
- Новых зависимостей, таблиц и миграций нет: `refresh_enc` и `device_id` в `platform_credentials` уже необязательны (у Instagram нет refresh-токена).
- Всё про Instagram лежит в `src/Integrations/Social/Instagram`, `InstagramConnections`, `InstagramConnectController`; конвейер получил две общие точки расширения: `PublishMedia::$url` и `Capabilities::$publicMediaUrls`.
- Пока владелец не включит `instagram` в `PLATFORMS_ENABLED`, сеть не видна в интерфейсе, а ее адаптер не используется.
